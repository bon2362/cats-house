# Вход и режим владельца — дизайн (этап 0 редактора)

Дата: 6 октября 2026
Статус: утверждённый дизайн

## Контекст

Владелец решил перенести ведение семейных данных на сайт: «Древо Жизни»
(AT5) больше не используется после финальной пересборки событий. Редактор
владельца строится этапами:

| № | Этап | Содержание |
|---|---|---|
| 0 | Вход и режим владельца | этот документ |
| 1 | Исправление людей | части имени, пол, даты (в т. ч. приблизительные), места, скрытие |
| 2 | Новые люди | «добавить ребёнка / родителя / супруга» от существующего человека |
| 3 | Исправление связей | удаление ошибочной связи или союза, перенос ребёнка, брак, развод, приёмный ребёнок |
| 4 | Биографии, фото, документы | текст, загрузка, публикация |

Род и занятие из AT5 не переносятся: они остаются только в исходном файле.

Сейчас ссылка «Вход для владельца» ведёт на `/login`, но такой страницы в
интерфейсе нет, и оболочка показывает главную. API уже умеет входить по паролю
(`POST /api/v1/auth/login`, cookie-сессия) и проверять сессию
(`GET /api/v1/admin/session`), но не умеет выходить и не ограничивает попытки.

## Цель

Владелец может войти на сайт, видеть, что он вошёл, и выйти. Сайт знает о
режиме владельца, чтобы следующие этапы показывали действия правки только ему.

## Страница входа `/login`

- Поле пароля и кнопка «Войти». Поле одноразового кода показывается только
  если сервер сообщает, что двухфакторный вход включён.
- После успешного входа — переход на адрес из параметра `next`, если это
  внутренний путь сайта (начинается с одного `/`); иначе — на главную.
  Ссылка «Вход для владельца» передаёт текущий путь и параметры в `next`.
- Ошибки по-русски, под формой:
  - `401` — «Неверный пароль.» (или текст сервера про одноразовый код);
  - `429` — «Слишком много попыток. Попробуйте через N мин.» (N из заголовка
    `Retry-After`, округление вверх);
  - сеть или `5xx` — «Сервер недоступен. Попробуйте позже.»
- Во время отправки кнопка неактивна; пароль не сохраняется в состоянии
  страницы после ответа.
- Если владелец уже вошёл, вместо формы: «Вы вошли как владелец» и кнопки
  «Выйти» и «На главную».

## Режим владельца на сайте

- Оболочка (`cats-house-app`) при загрузке запрашивает
  `GET /api/v1/auth/status` и хранит `isOwner`.
- В шапке: гость видит «Вход для владельца» (ссылка с `next`), владелец —
  «Владелец · Выйти». «Выйти» вызывает `POST /api/v1/auth/logout` и
  переключает шапку без перезагрузки.
- На узких экранах ссылка не скрывается полностью, как сейчас, а
  сокращается до «Владелец».
- Состояние владельца хранится в оболочке. Страницам оно передаётся в этапе 1,
  вместе с первыми кнопками правки; в этапе 0 кнопок правки нет.
- Ошибка запроса статуса считается режимом гостя.

## API

| Метод и путь | Ответ |
|---|---|
| `GET /api/v1/auth/status` | `200 {"authenticated": bool, "totp_required": bool}`; без личных данных, доступен всем |
| `POST /api/v1/auth/login` | без изменений по смыслу; добавляется ограничение попыток |
| `POST /api/v1/auth/logout` | `204`; очищает сессию; работает и без входа |

Ограничение попыток входа:

- ключ — адрес клиента (`request.client.host`);
- 5 неудачных попыток за 15 минут блокируют вход с этого адреса до истечения
  окна: `429` с заголовком `Retry-After` в секундах и текстом
  «Слишком много попыток входа.»;
- успешный вход сбрасывает счётчик адреса;
- счётчик хранится в памяти процесса: один владелец и один процесс API.
  За обратным прокси при публикации адрес клиента нужно будет брать из
  доверенного заголовка — это вне этапа 0.

Сессия: существующая подписанная cookie (`SessionMiddleware`, `same_site=lax`,
`https_only` в production), срок жизни 14 дней — значение по умолчанию.

## Смена пароля владельца

Пароль хранится в `.env` только как Argon2-хеш
(`CATS_HOUSE_OWNER_PASSWORD_HASH`). Команда `scripts/set-owner-password.py`:

- дважды спрашивает новый пароль через скрытый ввод, требует не менее
  12 символов и совпадения;
- записывает хеш в указанный `.env` (по умолчанию `.env` в корне), заменяя
  строку переменной или добавляя её; `$` в хеше экранируется как `$$`, как
  уже принято в `.env` проекта;
- не печатает ни пароль, ни хеш; сообщает, что API нужно перезапустить.

## Проверки

- API: статус для гостя и владельца, `totp_required`, выход очищает сессию,
  пятая неудача ведёт к `429` с `Retry-After`, успешный вход сбрасывает
  счётчик, блокировка не мешает другому адресу.
- Скрипт пароля: запись хеша в новый и существующий `.env`, экранирование
  `$`, отказ при несовпадении и коротком пароле; полученный хеш проверяется
  Argon2.
- Сайт (Vitest): страница входа — успешный вход и переход по `next`, отказ
  внешнего `next`, тексты ошибок 401/429/сети, поле кода по `totp_required`,
  вид «уже вошли»; шапка в обоих режимах и выход.
- Сквозной тест Playwright: реальный вход и выход в браузере; выполняется,
  только если задана `CATS_HOUSE_E2E_OWNER_PASSWORD`, иначе пропускается.
  Пароль не хранится в репозитории.

## Не входит в этап 0

Формы и кнопки правки (этап 1), включение двухфакторного входа (перед
публикацией), восстановление пароля по почте, несколько учётных записей.
