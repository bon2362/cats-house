# Ежедневная копия базы Neon в Google Drive — дизайн

Дата: 8 ноября 2026
Статус: утверждённый дизайн

## Контекст

Сайт переехал на Vercel + Neon (план `2026-11-07-vercel-neon-migration.md`).
Прежняя система копий (`~/archiving/cats-house/backup.py`, задание `launchd`
раз в час) по-прежнему копирует локальную базу в Docker, которая больше не
используется: правки после переезда не копируются никуда, кроме самого Neon.
Задача 4 плана переезда (`scripts/backup-neon.sh` на Mac) не делалась и этим
дизайном заменяется.

Проверка (8 ноября 2026): пакет `postgresql-binaries==17.11.0` из PyPI
(12 МБ, распакованный 35 МБ) запускает `pg_dump` и `pg_restore` 17.11 в
функции Vercel (Python 3.12, Amazon Linux 2023, регион `fra1`); системных
библиотек хватает, в `/tmp` 500 МБ. В Amazon Linux 2023 прогнан полный круг:
копия по TLS с PostgreSQL 17 → восстановление → побайтное совпадение файлов.

## Решения владельца

1. Копии делает сервис на Vercel, не Mac. Второй слой — встроенная история
   изменений Neon. Копии на Mac не нужны.
2. Только стандартный формат: копия восстанавливается обычным `pg_restore`,
   без кода проекта.
3. Раз в сутки, ночью.
4. Папка — своя у сервиса в «Мой диск»; доступ сервиса только к созданным им
   файлам. Папку можно перенести внутри «Мой диск».
5. Хранение: последняя копия за каждый из 30 последних дней и за каждый из 12
   последних месяцев, плюс всегда самая новая.
6. О сбое сообщает внешний сторож healthchecks.io письмом.
7. Отдельный проект Vercel `cats-house-backup`, не внутри API сайта.
8. Neon PostgreSQL 17.

## Устройство

Папка `apps/backup` в репозитории — отдельный проект Vercel (Root Directory
`apps/backup`), регион `fra1`, Python 3.12. Зависимость одна:
`postgresql-binaries==17.11.0`; запросы к Google и сторожу — стандартной
библиотекой (`urllib`). У проекта нет страниц, только адрес `GET /api/backup`.

Расписание (`apps/backup/vercel.json` → `crons`): `0 2 * * *` (UTC) — зимой
03:00–03:59, летом 04:00–04:59 по времени владельца (Vercel Hobby запускает
в пределах часа). `maxDuration` — 300 секунд.

Адрес отвечает `401` без заголовка `Authorization: Bearer <CRON_SECRET>`
(сравнение без утечки по времени); Vercel передаёт его сам.

### Порядок одного запуска

1. Распаковать программы PostgreSQL в `/tmp/pg` (если ещё не распакованы).
2. `pg_dump --format=custom --no-owner --no-privileges -f /tmp/<имя>.dump`.
   Подключение — из `BACKUP_DATABASE_URL` через переменные `PGHOST`,
   `PGPORT`, `PGUSER`, `PGPASSWORD`, `PGDATABASE`, `PGSSLMODE`; адрес не
   попадает в аргументы команды и в журналы. `sslmode` обязан быть `require`
   или строже, иначе отказ. Если подключение не удалось (Neon просыпается) —
   одна повторная попытка через 10 секунд.
3. Проверка копии: `pg_restore --list` читает оглавление без ошибок, и в нём
   есть данные (`TABLE DATA`) таблиц `people`, `unions`, `parent_children`,
   `events`, `media`. Иначе — сбой «копия неполная».
4. Имя файла — `cats-house-ГГГГ-ММ-ДДTЧЧММZ.dump` (время UTC).
5. Найти папку сервиса: `files.list` с `appProperties has {key='cats_house_backups' and value='1'}`,
   не в корзине. Нет — создать в корне «Мой диск» папку «Cat's House — копии
   базы» с этим свойством. Найдено несколько — взять самую старую.
6. Загрузить файл (`uploadType=multipart`, тип
   `application/octet-stream`) в папку и сравнить `md5Checksum` из ответа
   Drive с MD5 локального файла. Не совпало — удалить загруженный файл в
   корзину и считать запуск сбоем.
7. Хранение: перечислить в папке файлы вида `cats-house-…Z.dump` (не в
   корзине) и убрать лишние по правилу из решения 5, переводя их в корзину
   (`trashed=true`), а не удаляя окончательно. Хранение выполняется только
   после успешной загрузки новой копии.
8. Сигнал сторожу: `GET HEALTHCHECK_URL` при успехе; при любой ошибке —
   `POST HEALTHCHECK_URL/fail` с текстом ошибки до 500 символов, из которого
   вычищены адреса и пароли. Ошибка самого сигнала не превращает успешный
   запуск в сбой.
9. Ответ: `200 {"file": имя, "size": байт, "kept": число, "trashed": [имена]}`
   или `500 {"error": текст}`. Временный файл удаляется в обоих случаях.

### Google Drive

- OAuth-клиент Google Cloud типа «Desktop app», экран согласия External в
  статусе «In production» (в статусе Testing ключ истекает через 7 дней),
  разрешение только `https://www.googleapis.com/auth/drive.file`.
- Ключ обновления (`refresh token`) получает разовый скрипт
  `apps/backup/scripts/google-authorize.py` на Mac: открывает страницу
  согласия, принимает ответ на `127.0.0.1`, пишет ключ в файл вне
  репозитория с правами `600`, ключ на экран не печатает. В Vercel он
  попадает командой `cat <файл> | vercel env add GOOGLE_REFRESH_TOKEN production`.
- Перед запросами сервис получает временный ключ доступа:
  `POST https://oauth2.googleapis.com/token` (`grant_type=refresh_token`).

### Пользователь Neon только для чтения

В консоли Neon (SQL Editor) владелец выполняет готовые команды:
`CREATE ROLE cats_house_backup LOGIN PASSWORD …` и
`GRANT pg_read_all_data TO cats_house_backup`. Если Neon не разрешит
`pg_read_all_data` — `GRANT CONNECT` на базу, `USAGE` на схему `public`,
`SELECT` на все таблицы и последовательности и `ALTER DEFAULT PRIVILEGES`
на будущие таблицы. Используется прямой адрес Neon (без пула соединений) с
`sslmode=require`.

### Секреты (только проект `cats-house-backup`, окружение Production)

`BACKUP_DATABASE_URL`, `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`,
`GOOGLE_REFRESH_TOKEN`, `HEALTHCHECK_URL`, `CRON_SECRET`. Не хватает
любого — запуск сразу завершается сбоем с именем недостающей настройки
(без значений). Ничего из этого не попадает в git, аргументы команд или
журналы.

### Сторож

healthchecks.io, одна проверка: период 1 день, допуск 3 часа, письмо на
почту владельца. Сторож пишет и при сигнале «сбой», и при отсутствии
сигнала.

## Восстановление

`apps/backup/README.md` описывает:
- где лежат копии и как скачать нужную;
- восстановление в новую ветку Neon или пустую базу:
  `pg_restore --no-owner --no-privileges --exit-on-error -d <адрес> <файл>`;
- переключение сайта на восстановленную базу (переменная
  `CATS_HOUSE_DATABASE_URL` API-проекта на Vercel и повторное развёртывание);
- ежеквартальную проверку.

Скрипт `scripts/verify-backup-file.py <файл.dump>` на Mac (нужен Docker):
восстанавливает файл во временный контейнер `postgres:17-alpine` тем же
`pg_restore`, считает строки во всех таблицах и SHA-256 содержимого файлов
(`media.content`, `media.preview`), удаляет контейнер. Если задана
`CATS_HOUSE_SOURCE_DATABASE_URL` (только из окружения) — сравнивает с ней и
возвращает ненулевой код при расхождении.

## Уборка на Mac

- Выключить задание `com.ekoshkin.cats-house-backup` (`launchctl bootout`),
  файл задания из `~/Library/LaunchAgents` убрать; `~/archiving/cats-house`,
  папку `~/Cat's House backups` и локальную базу в Docker не трогать.
- README в `~/archiving/cats-house`: система выведена из работы, копии делает
  `apps/backup` на Vercel.
- `dashboard.py`: строка Cat's House показывает «копии делает Vercel — статус
  на healthchecks.io» вместо данных старой системы.
- План переезда: задача 4 помечается как заменённая этим дизайном.

## Проверки

Автоматические (`apps/backup/tests`, pytest):
- правило хранения: 30 дней, 12 месяцев, самая новая, чужие имена не
  трогаются, пустая папка;
- проверка секрета: нет заголовка, неверный, верный;
- недостающие настройки и `sslmode` без `require`;
- адрес базы и пароль не попадают в аргументы команды и в текст ошибки;
- Drive против поддельного HTTP-сервера: поиск и создание папки, загрузка,
  несовпадение `md5Checksum`, перевод старых копий в корзину, хранение не
  выполняется после неудачной загрузки;
- сторож: сигнал при успехе, `/fail` при ошибке, сбой сигнала не ломает
  успешный запуск;
- полный прогон с настоящим `pg_dump`/`pg_restore` из пакета против
  тестовой базы PostgreSQL 17 (testcontainers) с выдуманными людьми и
  файлами: копия проходит проверку, после восстановления файлы совпадают
  побайтно; копия без таблицы `media` отвергается;
- `scripts/verify-backup-file.py` на тестовой копии.

Ручные (после настройки секретов): запуск адреса вручную с секретом; файл в
Drive; сигнал на healthchecks.io; скачанная копия проходит
`verify-backup-file.py` и совпадает с Neon; повторный ночной запуск сам по
расписанию; адрес без секрета — `401`.

## Не входит

Копии на Mac, шифрование копий, копирование в другие облака, восстановление
одной кнопкой, отображение статуса копий на сайте, ежедневная автоматическая
проверка восстановления.
