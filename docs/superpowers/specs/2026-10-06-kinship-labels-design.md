# Подписи родства в семейном дереве — дизайн

## Цель

Показывать на карточке человека точное русское название его отношения к
центру дерева: «сестра», «троюродный брат», «зять», «пра-пра-внук» и так
далее. Название должно следовать из подтверждённых связей в архиве, а не из
фамилии, возраста или положения карточки на экране.

Пользователь видит короткую понятную подпись. Режим «Как связаны» получает
то же название и дополнительно показывает путь, из которого оно выведено.

## Данные и границы достоверности

`Древо 2.at5` хранит атомарные факты: участника семейного события, его роль
ребёнка/родителя, пол и союз. Импорт уже переводит их в `ParentChild` и
`Union`. Готовые слова «сестра», «троюродный брат» и «ятровка» в исходнике не
хранятся.

Вычислитель использует только эти факты:

- ориентированное ребро `родитель → ребёнок`;
- союз двух людей;
- пол, если он известен;
- тип связи родитель—ребёнок (`biological`, а в будущем — усыновление и
  другие явно введённые типы).

Он не делает выводов по фамилии, отчеству, дате рождения или порядку
карточек. Архивированная персона может участвовать в расчёте как безымянный
узел, но её имя и события не попадут в подпись или пояснение.

## Контракт API

API вычисляет подписи на сервере один раз для каждого человека в ответе
`GET /api/v1/tree/{person_id}`. Клиент не дублирует генеалогические правила.

Каждый `person` получает необязательное поле:

```json
"relationship": {
  "label": "троюродная сестра",
  "kind": "blood-collateral",
  "certainty": "confirmed"
}
```

`label` — готовый текст для карточки в верхнем регистре. `kind` нужен для
будущей легенды и тестов. `certainty` имеет значения `confirmed` и
`descriptive`. `descriptive` означает, что путь подтверждён, но у русского
языка нет одного общеупотребимого названия для этого конкретного случая.

Для корня поле не передаётся: интерфейс показывает «В ЦЕНТРЕ». Если связи
нет, поле также не передаётся, а карточка показывает «УЧАСТНИК СЕМЬИ», а не
вводящее в заблуждение «родственник».

## Алгоритм

1. Для каждого человека строится подграф кровных связей. Поиск ближайших
   общих предков ведётся только через `ParentChild`.
2. Отдельно строится граф союзов. Он применяется после определения кровной
   связи и никогда не превращает супругов в кровных родственников.
3. Среди нескольких путей выбирается путь с наименьшим числом рёбер. При
   равенстве приоритет: прямая кровь, родной/неполнородный сиблинг, боковая
   кровь, свойство, описательная связь.
4. Если несколько равноприоритетных путей дают разные точные термины,
   возвращается `descriptive` с нейтральным названием, например «родственница
   по двум семейным линиям». Никакой произвольный выбор не допускается.

## Словарь кровного родства

| Условие относительно центра | Мужчина | Женщина | Пол неизвестен |
|---|---|---|---|
| Родитель | отец | мать | родитель |
| Ребёнок | сын | дочь | ребёнок |
| Предок на 2 шага | дедушка | бабушка | дедушка или бабушка |
| Потомок на 2 шага | внук | внучка | внук или внучка |
| Предок дальше | `пра-` × (шаги − 2) + дедушка/бабушка | то же | предок |
| Потомок дальше | `пра-` × (шаги − 2) + внук/внучка | то же | потомок |
| Два общих биологических родителя | брат | сестра | сиблинг |
| Только общий отец | единокровный брат | единокровная сестра | единокровный сиблинг |
| Только общая мать | единоутробный брат | единоутробная сестра | единоутробный сиблинг |
| Брат/сестра родителя | дядя | тётя | дядя или тётя |
| Ребёнок брата/сестры | племянник | племянница | племянник или племянница |

Для боковой кровной линии определяется ближайший общий предок. Если оба
человека находятся от него на одинаковом расстоянии `d`:

- `d = 1`: брат или сестра;
- `d = 2`: двоюродный брат или двоюродная сестра;
- `d = 3`: троюродный брат или троюродная сестра;
- `d >= 4`: `N-юродный брат/сестра`, где `N = d`.

Если расстояния не равны, используются точные названия «дядя/тётя» или
«племянник/племянница» для разницы в одно поколение. Для более сложного
случая используется понятная составная подпись: «двоюродный дядя»,
«троюродная племянница», либо `descriptive`: «потомок двоюродного брата».

Префикс выводится в читаемом виде через дефис: `пра-пра-пра-внук`. Это
сознательное UI-правило; оно легче читается, чем слитное историческое
написание.

## Свойство: родство через союз

Свойство вычисляется только по действительному союзу и подтверждённым
кровным связям. Когда пол неизвестен, показывается точное описательное
название, а не гендерный термин.

| Условие относительно центра | Подпись |
|---|---|
| Участник союза | муж / жена / супруг |
| Муж дочери или сестры | зять |
| Жена сына | невестка; пояснение «жена сына» |
| Отец/мать супруга для мужчины | тесть / тёща |
| Отец/мать супруга для женщины | свёкор / свекровь |
| Брат/сестра жены | шурин / свояченица |
| Брат/сестра мужа | деверь / золовка |
| Муж сестры | зять |
| Жена брата | невестка; пояснение «жена брата» |
| Жёны двух родных братьев, относительно друг друга | ятровка |

«Сноха» не используется как основная автоматическая подпись: современное
употребление пересекается с «невесткой» и зависит от точки зрения семьи.
В подробном пояснении допустима формулировка «жена сына».

Если правило свойства зависит от пола, которого нет в данных, интерфейс
показывает «родственник по браку» с пояснением пути, например «супруг сестры
центра».

## Сводные и приёмные связи

- `сводный брат/сестра` допускается только когда у людей нет общего родителя,
  но один родитель каждого состоит в союзе с другим;
- для усыновления добавляется явный префикс `приёмный` только если тип
  `ParentChild.relationship_type` это подтверждает;
- при неполных данных не показывается «родной», «сводный» или «приёмный».

## Отображение и пояснение

Карточка показывает основную подпись. По нажатию на карточку в инспекторе
добавляется строка «Почему так»: например, «общие родители: Николай Кошкин и
Вера» или «жёны двух родных братьев». Для скрытых людей имена в такой строке
заменяются на «скрытый родственник».

## Проверки

Тесты API и интерфейса покрывают как минимум:

1. Пётр и Ксения Кошкины — брат и сестра с двумя общими родителями.
2. Единокровные и единоутробные сиблинги.
3. Прямую линию до `пра-пра-пра-внука`.
4. Двоюродных и троюродных брата/сестру через ближайшего общего предка.
5. Дядю, тётю, племянника и племянницу.
6. Зятя, невестку, деверя, золовку, шурина, свояченицу и ятровку.
7. Неизвестный пол, несколько равных путей и скрытого промежуточного человека.
8. Отсутствие ложной подписи при совпадении фамилий без подтверждённого пути.

## Не входит в первую реализацию

Крёстные, кумовство, названые родственники и культурно-исторические
варианты терминов не выводятся автоматически: их нет в модели исходного
файла как надёжных связей.
