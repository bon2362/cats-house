# Исправление людей — дизайн (этап 1 редактора владельца)

Дата: 6 октября 2026
Статус: утверждённый дизайн (решения из раздела «Принятые решения» приняты
автором спецификации; владелец может их пересмотреть до реализации)

## Контекст

Этап 0 (`2026-10-06-owner-access-design.md`) дал вход владельца и режим
владельца в шапке. Этап 1 позволяет владельцу исправлять уже существующих
людей. Сайт становится единственным местом ведения данных; «Древо Жизни»
(AT5) после первой правки больше не синхронизируется — пересборка событий
`scripts/sync-at5-events.py` сама останавливается, как только в журнале
правок появляется запись.

Состояние данных на момент дизайна: 280 людей, имя хранится одной строкой
`people.display_name` («Имя Отчество Фамилия», совпадает с AT5 у всех 280),
части имени в AT5 хранятся раздельно; у каждого человека не больше одного
события рождения и одного события смерти; мест, приблизительных дат и
биографий нет; дерево показывает даты сырым текстом GEDCOM (`6 APR 1926`).

## Цель

Владелец на странице человека нажимает «Изменить» и исправляет: фамилию, имя,
отчество, фамилию при рождении, пол, дату и место рождения, факт, дату и место
смерти; может скрыть человека с публичного сайта и вернуть скрытого. Каждое
сохранение записывается в журнал правок. Посетители видят результат сразу.

## Принятые решения

1. **Части имени — отдельные поля.** В `people` добавляются `surname`,
   `given_name`, `patronymic`, `birth_surname` (все необязательные, до 255
   символов). `display_name` остаётся и при каждом сохранении собирается как
   «Имя Отчество Фамилия» из непустых частей — поиск, дерево, родство и
   экспорт продолжают работать с ним без изменений.
2. **Части имени заполняются из AT5 один раз.** Команда
   `scripts/backfill-name-parts.py --at5 … [--apply]` берёт фамилию, имя и
   отчество из AT5 по `source_uid` и заполняет только людей, у которых все
   части пусты. `display_name` при этом не меняется. Без `--apply` — пробный
   прогон с отчётом из чисел. Фамилий при рождении в AT5 нет.
3. **Сохранение требует хотя бы имя или фамилию.** Пустой человек не
   сохраняется.
4. **Фамилия при рождении** показывается на странице человека строкой
   «урождённая / урождённый / при рождении X» (по полу) и участвует в поиске;
   в `display_name` не входит.
5. **Пол:** «мужской», «женский», «не указан» (`M`, `F`, пусто).
6. **Даты — только структурированный ввод**, без свободного текста:
   вид даты «точно / около / до / после / между», год обязателен, месяц и
   день необязательны (день — только вместе с месяцем), для «между» — вторая
   дата, строго позже первой. Только григорианский календарь, годы от 1000 до
   текущего. Хранение — существующие поля события: текст в стиле GEDCOM
   (`6 APR 1926`, `ABT 1900`, `BEF MAR 1944`, `BET 1900 AND 1905`), вид даты
   и границы `date_lower`/`date_upper` с учётом точности (год → весь год,
   месяц → весь месяц; «до» — только верхняя граница, «после» — только нижняя).
7. **Одно событие рождения и одно событие смерти на человека.** Форма правит
   их; если по какой-то причине событий несколько, правится самое раннее, а
   сохранение отклоняется с понятной ошибкой, чтобы ничего не потерять.
8. **Смерть — три состояния:** «нет сведений» (события нет), «умер(ла), дата
   неизвестна» (событие без даты), «дата смерти» (событие с датой). Рождение —
   два: «нет сведений» или дата. Место — свободный текст до 512 символов,
   пробелы по краям обрезаются, пустое место = нет места.
9. **Нераспознанная дата.** Если сохранённый текст даты не разбирается в
   структуру (сейчас таких нет), форма показывает его как есть с пометкой
   «дата в старом формате» и сохраняет без изменений, пока владелец не задаст
   новую дату.
10. **Скрытие и возврат.** «Скрыть человека» (с подтверждением) использует
    существующее архивирование; добавляется «Вернуть на сайт». Скрытый человек
    для посетителей выглядит как сейчас («Сведения скрыты» в дереве, 404 на
    странице). Владелец находит скрытых через поиск в шапке (в режиме
    владельца поиск включает скрытых с пометкой «скрыт») и открывает их
    страницу правки по обычному адресу `/people/{id}`.
11. **Журнал правок.** Одно сохранение — одна запись `change_logs` с
    прежними и новыми значениями только изменившихся полей
    (`entity_type="person"`). Сохранение без изменений запись не создаёт.
    Скрытие и возврат — отдельные записи, как сейчас.
12. **Даты по-русски везде.** Подписи дат на карточках дерева и в инспекторе
    проходят через тот же русский формат, что и страница человека:
    `6 апреля 1926`, `ок. 1900`, `до марта 1944`, `после 1950`,
    `между 1900 и 1905`.
13. **Где правка в интерфейсе.** На странице человека владелец видит кнопку
    «Изменить», открывающую форму на месте блока заголовка. Адрес
    `/people/{id}?edit=1` открывает страницу сразу с формой. Во всплывающей
    карточке дерева владелец видит ссылку «Изменить» на этот адрес.

## API (только владелец, `require_owner`)

| Метод и путь | Назначение |
|---|---|
| `GET /api/v1/admin/people?query=` | поиск для владельца, включая скрытых: `[{id, display_name, years, is_archived}]`, до 20 результатов |
| `GET /api/v1/admin/people/{id}` | данные формы (`EditablePerson`), в том числе для скрытого |
| `PATCH /api/v1/admin/people/{id}` | сохранение формы целиком, ответ — `EditablePerson` |
| `POST /api/v1/admin/people/{id}/archive` | скрыть (есть) |
| `POST /api/v1/admin/people/{id}/restore` | вернуть на сайт (новое) |

`EditablePerson`:

```json
{
  "id": "…", "display_name": "Пётр Николаевич Кошкин", "is_archived": false,
  "surname": "Кошкин", "given_name": "Пётр", "patronymic": "Николаевич",
  "birth_surname": null, "sex": "M",
  "birth": {"date": {"qualifier": "exact", "year": 1901, "month": null, "day": null, "end": null}, "date_text": "1901", "place": null},
  "death": {"status": "deceased", "date": {"qualifier": "exact", "year": 1944, "month": null, "day": null, "end": null}, "date_text": "1944", "place": null}
}
```

`birth` — `null` или `{date, date_text, place}`; `death.status` —
`"unknown"` или `"deceased"`. `date` — `null` или
`{qualifier, year, month, day, end}`, где `end` — `{year, month, day}` только
для `"between"`. `date_text` — только для чтения (исходный текст, нужен для
п. 9).

Тело `PATCH` — те же поля без `id`, `display_name`, `is_archived`,
`date_text`; `birth.date_text_keep: true` и `death.date_text_keep: true`
означают «оставить нераспознанную дату без изменений» (п. 9).

Ошибки проверки — `422` с текстом на русском в `detail` (строка): «Укажите
имя или фамилию.», «В этом месяце нет такого дня.», «Год должен быть от 1000
до N.», «Вторая дата периода должна быть позже первой.», «День можно указать
только вместе с месяцем.», «У человека несколько событий рождения — исправьте
их отдельно.» Ошибки типов от валидации запроса остаются стандартными, и
интерфейс показывает для них «Проверьте заполнение полей.»

Публичный `GET /api/v1/people/{id}` дополнительно отдаёт `birth_surname` и
`sex`; поиск `GET /api/v1/people?query=` ищет и по `birth_surname`.

## Интерфейс

- Оболочка передаёт состояние владельца страницам: `cats-person-card
  .isOwner`, `cats-tree-page .isOwner`.
- Страница человека владельцу показывает «Изменить»; форма (`cats-person-
  editor`) заменяет заголовок страницы до сохранения или отмены. Поля: фамилия,
  имя, отчество, фамилия при рождении, пол; блок «Рождение» (нет сведений /
  дата + место); блок «Смерть» (нет сведений / умер(ла), дата неизвестна /
  дата + место); кнопки «Сохранить» и «Отмена»; внизу «Скрыть человека» или
  «Вернуть на сайт».
- Ввод даты (`cats-date-input`): вид даты, день, месяц (список названий),
  год; для «между» — вторая дата; под полем — как дата будет показана
  посетителям (`ок. 1900`).
- После сохранения страница перезагружает публичные данные и показывает
  «Сохранено». Ошибка сервера показывается над кнопками; введённые значения
  не теряются.
- Скрытый человек: публичный запрос даёт 404; если владелец вошёл, оболочка
  открывает форму этого человека с плашкой «Человек скрыт с сайта» и кнопкой
  «Вернуть на сайт».
- Поиск в шапке у владельца идёт через `GET /api/v1/admin/people`, скрытые
  помечены «скрыт».
- Инспектор дерева у владельца: ссылка «Изменить» на `/people/{id}?edit=1`.

## Проверки

- Даты: сборка текста и границ для каждого вида и точности, разбор обратно
  (включая весь импорт: `6 APR 1926`, `MAR 2004`, `1944`), русский формат,
  все тексты ошибок.
- Имена: сборка `display_name`, требование имени или фамилии, поиск по
  фамилии при рождении.
- Заполнение частей имени из AT5: только пустые люди, `display_name` не
  меняется, пробный прогон не пишет, отчёт из чисел.
- Сервис и API: доступ только владельцу (401 гостю), чтение и сохранение
  каждого поля, удаление и создание событий рождения и смерти, три состояния
  смерти, журнал только изменившихся полей и отсутствие записи без
  изменений, скрытие и возврат, поиск владельца со скрытыми, 404 для
  несуществующего.
- Дерево: подписи дат на русском, в том числе для приблизительных.
- Интерфейс (Vitest): ввод даты, форма (заполнение, сохранение, ошибки,
  отмена, скрытие с подтверждением, возврат), кнопка «Изменить» только у
  владельца, `?edit=1`, скрытый человек у владельца, поиск владельца,
  ссылка в инспекторе.
- Сквозной тест (только с `CATS_HOUSE_E2E_OWNER_PASSWORD`): вход, открытие
  формы у реального человека, отмена без сохранения. Сохранение в сквозном
  тесте не выполняется, чтобы не менять реальные данные.

## Не входит в этап 1

Добавление людей (этап 2), правка связей и союзов (этап 3), биографии, фото и
документы (этап 4), признак «жив» и правила приватности для живых, несколько
вариантов имени, юлианские даты, отмена правки из журнала, одновременная
правка из нескольких вкладок.
