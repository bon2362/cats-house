# Этап 2 — собственная генеалогическая модель и импорт GEDCOM

Дата: 4 октября 2026  
Статус: согласованный дизайн, ожидает проверки письменной спецификации владельцем

## Цель

Cat's House получает собственную реляционную модель генеалогических данных и
единовременно импортирует реальный файл `1.ged` локально, в непубличную базу
данных владельца. После принятия импорта сайт, а не «Древо Жизни», становится
единственным рабочим местом для дальнейших изменений.

Исходные `Древо 2.at5`, `1.ged` и `1.xml` не попадают в Git и не
загружаются в сторонние сервисы. Они сохраняются владельцем неизменяемым
историческим архивом; регулярной синхронизации с ними нет.

## Границы этапа

В этап входят:

- схема PostgreSQL для людей, союзов, родительских связей, событий, заметок,
  источников и материалов;
- сохранение внешнего идентификатора GEDCOM `_UID` как `source_uid` человека;
- разбор GEDCOM 5.5.1 из «Древа Жизни» собственным компонентом Cat's House;
- непубличный предварительный отчёт и атомарное применение импорта;
- импорт реального `1.ged` только на локальной машине владельца и отчёт для
  ручной сверки.

Не входят: публичное дерево, поиск, редактор данных, импорт AT5/XML,
синхронизация с внешними программами, экспорт и медиафайлы. AT5 и XML нужны
как архив и материал для будущей сверки, а не как дополнительный источник
автоматического слияния.

## Модель данных

| Сущность | Назначение |
| --- | --- |
| `Person` | Человек: отображаемое имя, структурированные варианты имени, пол, даты, биография, `source_uid`. |
| `Union` | Союз двух людей; допускает несколько союзов у человека и собственные события. |
| `ParentChild` | Связь ребёнка с родителем и явный тип связи. Импорт GEDCOM создаёт биологический тип, если иной не указан. |
| `Event` | Личное или семейное событие: тип, исходная строка даты, нормализованная дата при возможности, место и описание. |
| `Note` | Свободный текст, который в следующих этапах можно прикрепить к человеку, событию или источнику. |
| `Source` | Источник факта и связанные с ним ссылки на заметки. |
| `Media` | Метаданные фото или документа; на этом этапе без фактической загрузки файлов. |
| `ImportRun` | Попытка импорта: исходное имя файла, контрольная сумма, состояние, количества и время. |
| `ImportIssue` | Предупреждение или ошибка разбора с уровнем, сообщением и номером строки GEDCOM. |

Сущности имеют собственные UUID Cat's House. Идентификаторы GEDCOM (`@I…@`,
`@F…@`) хранятся только как данные конкретного импорта и не становятся
постоянными публичными идентификаторами API.

## Импорт

Импорт состоит из двух закрытых действий владельца:

1. `POST /api/v1/admin/imports/preview` принимает GEDCOM, проверяет кодировку
   и структуру, строит отчёт и создаёт `ImportRun` без генеалогических записей
   в рабочей базе.
2. `POST /api/v1/admin/imports/{id}/apply` применяет только успешный
   предпросмотр. Все записи создаются в одной транзакции PostgreSQL. Ошибка
   откатывает весь импорт.
3. `GET /api/v1/admin/imports/{id}` возвращает владельцу состояния, контрольные
   количества и список проблем.

Первый успешный импорт создаёт начальный набор Cat's House. Повторное
применение не выполняется автоматически и не перезаписывает существующие
данные; отдельный режим повторной миграции будет спроектирован позднее.

Для разбора используется собственный ограниченный GEDCOM-компонент, а не
Gramps и не отдельный сервис. Он поддерживает нужные записи `INDI`, `FAM`,
`NAME`, `SEX`, `BIRT`, `DEAT`, другие события, `DATE`, `PLAC`, `NOTE`, `SOUR`,
`OBJE`, `FAMC`, `FAMS`, `HUSB`, `WIFE`, `CHIL` и `_UID`. Неизвестные теги не
теряются молча: они попадают в предупреждения отчёта.

## Отчёт и приёмка

Предпросмотр показывает количества людей, союзов, родительских связей,
событий, мест, заметок, источников, материалов и отсутствующих файлов, а
также предупреждения и ошибки. Импорт с ошибками не применяется.

После применения владелец сверяет минимум:

- 285 людей;
- 398 событий;
- кириллицу и исходные варианты имён;
- точные, приблизительные и диапазонные даты;
- несколько известных ветвей, включая несколько союзов, детей из разных
  союзов и неполные сведения.

Реальный файл `1.ged` используется только в локальном запуске. Его результат
не публикуется, пока владелец не примет отчёт; открытие публичного просмотра
является задачей следующего этапа.

## Ошибки, безопасность и проверка

Только авторизованный владелец может создавать предпросмотр или применять
импорт. Невалидная кодировка, нарушенная иерархия GEDCOM, ссылки на
несуществующие записи и неподдерживаемые обязательные данные становятся
ошибками с номером строки. Неизвестные необязательные теги становятся
предупреждениями.

Автоматические тесты проверяют разбор кириллицы, `_UID`, дат, сложных семей,
связей и контрольных количеств; отсутствие частичных записей после ошибки;
и запрет административных маршрутов для неавторизованного пользователя.
