# Семейное дерево — семейные блоки и маршрутизация линий

Дата: 6 октября 2026  
Статус: утверждённый дизайн

## Цель

Сделать линии дерева самостоятельным и достоверным объяснением родства: по ним
видно, кто образует союз, от какого союза происходят дети и куда ведёт каждая
ветвь. Это одинаково относится к «Ближайшим», «Предкам», «Потомкам»,
«Смешанному», «Как связаны» и «Всей семье».

## Семейный блок

Единица раскладки — семейный блок, а не отдельная карточка. Он содержит одного
или двух известных партнёров, узел союза, видимых детей этого союза и порты
`partner`, `children`, `parent` для маршрутов. Союз не выдумывается: блок
создаётся только из `unions` либо для одного известного родителя со связью без
`union_id`.

## Линии

| Вид | Правило |
| --- | --- |
| `partner` | Короткая линия между партнёрами через узел их союза. |
| `parent-child` | Из `children`-порта узла союза — к шине детей, затем к границе каждой карточки ребёнка. Двух дублирующих линий от родителей к ребёнку нет. |
| `continuation` | Пунктир к интерактивному маркеру с числом скрытых людей или семей; только когда ветвь сознательно свёрнута текущим режимом. |

Круг показывается только на узле союза, если есть видимый ребёнок, и находится
в фактической точке ветвления. У каждого маршрута оба конца — граница карточки,
видимый узел союза или интерактивный маркер. Свободные концы запрещены.

## Раскладка

1. Из ответа API строится граф семейных блоков.
2. Уровни поколений определяются только родительскими связями; партнёры и союз
   остаются на одном уровне.
3. Блоки упорядочиваются до координат: партнёры рядом, дети одного союза
   занимают соседний диапазон следующего поколения, посторонняя карточка не
   разрывает блок.
4. Измеряются реальные размеры HTML-карточек. Затем рассчитываются координаты
   блоков, каналов линий и полос поколений.
5. Ортогональные маршруты проходят только по свободным каналам и не пересекают
   карточки. При конфликте меняется порядок блоков или канал, а не рисуется
   линия поверх карточки.
6. При нескольких союзах одна личность может появиться в нескольких блоках,
   только если это устраняет пересечение или делает детей союза однозначными.
   Каждая копия открывает ту же запись человека.

## Неполные данные и границы

- Один известный родитель — одинарный семейный блок. Отсутствующий второй
  родитель не создаётся и не подписывается.
- Скрытый партнёр остаётся нейтральной карточкой «Сведения скрыты».
- Невидимый для режима союз или ребёнок даёт `continuation`, а не обычную
  линию к пустому месту.
- `continuation` не заменяет реальную связь, когда оба её участника видимы.

## Режимы

| Режим | Показываемые блоки |
| --- | --- |
| Ближайшие | Родители центра, его союзы и дети, братья/сёстры с видимыми партнёрами; дальние ответвления свёрнуты. |
| Предки | Родительские блоки старших поколений; союзы потомков свёрнуты. |
| Потомки | Союзы и дети младших поколений; родительские блоки предков свёрнуты. |
| Смешанное | Предки и потомки центра, с партнёрами внутри соответствующих блоков. |
| Как связаны | Только кратчайшая подтверждённая цепочка и задействованные семейные блоки. |
| Вся семья | Карта компонента: окружение центра раскрыто, дальние блоки по умолчанию свёрнуты в `continuation`; поиск и раскрытие ведут к любому человеку. Не обещает традиционное читаемое дерево из всех 280 карточек одновременно. |

## Доступность и взаимодействие

- Карточки остаются HTML-кнопками и сохраняют существующие click/drag,
  инспектор, клавиатуру и переход к человеку.
- Узел союза и маркер продолжения имеют доступное текстовое описание; маркер —
  кнопка, раскрывающая именно связанный блок.
- SVG содержит только полосы, линии, узлы и маркеры; личные данные остаются в
  HTML-карточках.

## Приёмка

1. У Петра Кошкина в «Ближайших» виден путь «родители Марии → Мария → союз
   Марии и Петра».
2. У каждой линии допустимые концы; нет свободных сегментов в «Потомках» и
   «Всей семье».
3. Дети соединены только с узлом собственного союза; другой блок не пересекает
   этот маршрут.
4. Несколько союзов не приписывают детей соседнему союзу и не создают ложных
   линий.
5. На реальной базе «Вся семья» позволяет найти и сделать центром любого из
   280 людей, не превращая дальние связи в непонятную сетку.
6. Сохраняются требования к полным именам, медиа, popover и drag.

## Границы

- API и исходная модель не меняются: используются `unions`,
  `parent_links.union_id` и скрытые записи.
- Не добавляются догадки о семьях, родителях и типах родства.
- Не меняются подписи родства и архивные данные.
