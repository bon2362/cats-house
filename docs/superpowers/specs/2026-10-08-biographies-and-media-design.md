# Биографии, фото и документы — дизайн (этап 4 редактора владельца)

Дата: 8 октября 2026
Статус: утверждённый дизайн

## Контекст

Этапы 0–3 дали вход владельца, правку людей, добавление родственников и
исправление связей. Этап 4 по таблице этапов (`2026-10-06-owner-access-design.md`)
— «Биографии, фото, документы: текст, загрузка, публикация».

На момент дизайна: в архиве 285 человек, ни одной биографии и ни одного
файла. На сервере есть заготовки без интерфейса: `POST /admin/media` (файл в
S3), `PATCH /admin/media/{id}/publish`, `POST /admin/media/{id}/links`,
`GET /media/{id}` (временная ссылка S3 на час). Дерево показывает первый
опубликованный файл человека как фото — даже если это PDF. Скрипты
`create-local-backup.py`/`restore-local-backup.py` берут файлы из S3.

## Решения, принятые с владельцем

1. Портрет + галерея: один главный портрет (шапка страницы, карточка в
   дереве) и галерея остальных фото и сканов с подписью и датой.
2. Файл принадлежит одному человеку.
3. Файл виден всем сразу после загрузки; владелец может его скрыть.
4. Биография — простой текст, абзацы через пустую строку.
5. Файлы хранятся в базе данных (фото пока нет, будет несколько). S3 для
   файлов больше не используется.

## Данные

Миграция `0009`:
- `media`: `content` (bytea, файл), `preview` (bytea, уменьшенная копия,
  только у фото), `caption` (текст), `date_label` (строка до 64),
  `created_at` (время загрузки), `is_deleted` (по умолчанию false);
  `storage_key` становится необязательным.
- `people`: `portrait_media_id` (ссылка на `media`, необязательная).

Файл привязан к человеку существующей записью `media_links` (ровно одна
связь с человеком на файл, созданная при загрузке). Привязка к событиям в
модели остаётся, но интерфейса для неё нет.

Списки читают файлы без содержимого: `content`/`preview` загружаются только
при отдаче файла.

## Правила

### Загрузка
- Форматы: JPEG, PNG, PDF. Тип определяется по содержимому файла, а не по
  имени или заголовку браузера: JPEG начинается с `FF D8 FF`, PNG — с
  `89 50 4E 47`, PDF — с `%PDF-`. Иначе — «Разрешены JPEG, PNG и PDF.»
- Размер до 10 МБ, иначе «Файл не должен превышать 10 МБ.»
- Фото должно открываться как изображение, иначе «Файл повреждён или это не
  изображение.»
- Для фото делается уменьшенная копия: поворот по EXIF, ширина и высота не
  больше 400 пикселей, JPEG качества 85 (прозрачность PNG — на белом фоне).
  Библиотека Pillow.
- Новый файл опубликован (`is_published = true`), подпись и дата пусты.
- Загрузка к несуществующему человеку — 404.

### Подпись и дата
Подпись — до 500 знаков, дата — свободный текст до 64 знаков («1953»,
«около 1950»). Пробелы по краям убираются, пустое значение хранится как
отсутствие. Длиннее — «Подпись не может быть длиннее 500 символов.»,
«Дата не может быть длиннее 64 символов.»

### Скрыть / показать
`is_published` меняется. Если скрывается портрет, он перестаёт быть
портретом.

### Портрет
Портрет — одно фото (JPEG или PNG) этого человека, опубликованное и не
удалённое. Отказы: «Портретом может быть только фото.», «Скрытое фото не
может быть портретом.», «Этот файл принадлежит другому человеку.» Портрет
можно убрать (`null`).

### Удаление
«Удалить» ставит `is_deleted = true`: файл исчезает с сайта у всех, запись
остаётся в базе (вернуть можно вручную). Если это портрет — портрет
убирается. Удалённый файл недоступен ни по одному адресу; повторное
удаление и правка удалённого — 404 «Файл не найден.»

### Биография
Пробелы по краям убираются, переводы строк приводятся к `\n`, пустой текст
хранится как отсутствие. До 20 000 знаков, иначе «Биография не может быть
длиннее 20000 символов.»

### Видимость
Гость видит файл, если он опубликован, не удалён и человек не скрыт.
Владелец видит все неудалённые файлы. Это же правило действует для адресов
файлов: скрытый файл гость не получит и по прямой ссылке (404).

### Журнал
Каждое действие пишется в журнал правок: загрузка (`media`, `before = {}`,
`after` — человек, имя файла, тип), правка подписи/даты, скрытие/показ,
удаление (`media`, до/после изменённых полей), портрет и биография
(`person`, до/после `portrait_media_id` или `biography`).

## API

Публичное:

| Метод и путь | Назначение |
|---|---|
| `GET /api/v1/people/{id}` | добавляются `portrait` (`{id, preview_url, file_url}` или `null`) и `media` — видимые гостю файлы человека по времени загрузки: `[{id, original_filename, media_type, caption, date_label, file_url, preview_url}]` (`preview_url` — `null` у PDF) |
| `GET /api/v1/media/{id}/file` | сам файл (видимость — см. выше) |
| `GET /api/v1/media/{id}/preview` | уменьшенная копия фото; у PDF — 404 |
| `GET /api/v1/tree/{id}` | `photo_url` — уменьшенная копия портрета (если портрет виден гостю) |

Файлы отдаются с `Content-Type` из базы, `Content-Disposition: inline` с
именем файла, `X-Content-Type-Options: nosniff`, `Cache-Control: private,
max-age=300`.

Владелец:

| Метод и путь | Назначение |
|---|---|
| `GET /api/v1/admin/people/{id}/media` | все неудалённые файлы человека, плюс `is_published`, `is_portrait` |
| `POST /api/v1/admin/people/{id}/media` | загрузка одного файла (`multipart`, поле `file`) → `201` вид файла |
| `PATCH /api/v1/admin/media/{id}` | `{caption?, date_label?, is_published?}` → `200` вид файла |
| `DELETE /api/v1/admin/media/{id}` | удаление → `204` |
| `PUT /api/v1/admin/people/{id}/portrait` | `{media_id \| null}` → `200 {portrait_media_id}` |
| `PATCH /api/v1/admin/people/{id}/biography` | `{biography}` → `200 {biography}` |

`GET /api/v1/admin/people/{id}` (форма этапа 1) получает поле `biography`.
Старые `POST /admin/media`, `PATCH /admin/media/{id}/publish`,
`POST /admin/media/{id}/links`, `GET /media/{id}` удаляются: интерфейса у них
нет, их заменяют адреса выше.

Ошибки — как раньше: `422` с русским текстом, `404` «Человек не найден.» /
«Файл не найден.», `401` гостю.

## Настройки и резервная копия

- `CATS_HOUSE_S3_ENDPOINT` и `CATS_HOUSE_S3_BUCKET` становятся
  необязательными (старые `.env` с ними продолжают работать). Код S3 и
  зависимость `boto3` удаляются.
- JSON-архив сохраняет новые поля (подпись, дата, время загрузки, скрыт,
  удалён, портрет человека). Скрипт резервной копии, как и раньше,
  складывает сами файлы рядом с JSON (`cats-house-…-media/`), но берёт их из
  базы; восстановление кладёт их обратно в базу и заново делает уменьшенные
  копии. Старые архивы без новых полей восстанавливаются (поля пустые).

## Интерфейс

Страница человека:
- Шапка: портрет (уменьшенная копия) вместо монограммы, если он есть.
  Биография больше не дублируется в шапке.
- «Биография»: гость видит текст абзацами или «Биография пока не написана».
  Владелец — кнопку «Изменить»: поле текста со счётчиком «N из 20000»,
  «Сохранить», «Отмена»; ошибка сервера показывается, текст не теряется
  (`cats-biography-section`).
- «Фото и документы» (`cats-media-section`): гость видит плитки — у фото
  уменьшенная копия, у PDF значок документа и имя файла; под плиткой подпись
  и дата; нажатие открывает полный файл в новой вкладке; пусто — «Фото и
  документы пока не добавлены». На телефоне две колонки.
- Владелец там же: «Загрузить файлы» (несколько сразу, загружаются по
  очереди; у каждого «загружается…», затем готово или причина отказа). У
  плитки: «Изменить подпись» (поля «Подпись», «Дата»; «Сохранить»,
  «Отмена»), «Сделать портретом» (только фото; у портрета метка «Портрет» и
  «Убрать портрет»), «Скрыть»/«Показать» (скрытая плитка блёклая с меткой
  «скрыт»), «Удалить» (подтверждение). После изменения страница получает
  `person-changed`.
- Страница скрытого человека (только владелец) получает те же два блока.

Дерево показывает на карточке уменьшенную копию портрета.

## Проверки

Сервер: загрузка каждого формата, отказы (тип, размер, битое фото),
уменьшенная копия и поворот, видимость файлов гостю и владельцу (скрытый,
удалённый, скрытый человек), портрет и его отказы, сброс портрета при
скрытии и удалении, подпись и дата, биография, журнал, дерево берёт только
портрет, архив и восстановление с файлами, необязательные настройки S3.
Интерфейс: биография (просмотр, правка, ошибка, отмена), галерея гостя,
загрузка нескольких файлов с отказом одного, все кнопки плитки,
подтверждение удаления, портрет в шапке. Сквозной тест (только с паролем
владельца): открыть «Изменить» у биографии и отменить; ничего не
сохраняется.

## Не входит в этап 4

Привязка файлов к событиям, общие фото нескольких людей, просмотр в
увеличенном окне на странице, поворот и обрезка, HEIC и Word, перенос файлов
в отдельное хранилище.
