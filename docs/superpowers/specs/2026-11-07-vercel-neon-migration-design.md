# Переезд Cat’s House на Vercel и Neon — дизайн

Дата: 7 ноября 2026  
Статус: предложено для выполнения

## Цель

Дать сайту постоянный доменный адрес без постоянно включённого Mac, сохранив текущие публичные страницы, вход владельца с TOTP и полный набор семейных данных, включая фотографии и документы.

## Исходное состояние

- Временная публикация работает с Mac через Cloudflare Tunnel (`scripts/serve-public.sh`).
- API — FastAPI и PostgreSQL; веб-интерфейс — Vite/Lit.
- Фотографии, документы и их уменьшенные копии уже находятся в PostgreSQL (миграция `0009_media_in_database.py`), а не в S3.
- Браузер использует относительные адреса `/api/v1/...`; cookie владельца рассчитана на один адрес сайта.
- Владелец покупает домен в Namecheap. Cloudflare будет использоваться только как DNS-провайдер, когда домен будет выбран.

## Выбранный подход

Использовать два Vercel-проекта в уже существующей учётной записи:

1. **Web**: корень `apps/web`, статическая Vite-сборка и основной домен.
2. **API**: корень `apps/api`, FastAPI как одна Vercel Function и технический поддомен `api.<домен>`.

Проект Web будет переписывать запросы `/api/:path*` во второй проект. В адресной строке и с точки зрения браузера API останется на основном домене: текущие `fetch('/api/...')` и cookie входа не потребуют смены.

Neon заменяет локальный PostgreSQL. В API используется Neon pooled connection string с TLS; на serverless-платформе SQLAlchemy не держит постоянный пул соединений между вызовами. Данные переносятся одним контролируемым окном обслуживания через `pg_dump` и `pg_restore` после независимой локальной копии.

## Границы

Входит:

- подготовка конфигурации Vercel и Neon;
- корректная работа с IP посетителя и ограничением частоты запросов на Vercel;
- безопасная миграция существующей базы, включая BLOB-данные медиа;
- DNS, HTTPS, проверка и откат;
- ежедневная переносимая копия Neon на Mac владельца и проверка восстановления.

Не входит:

- перенос медиа в Cloudflare R2;
- изменение публичной функциональности, модели данных или интерфейса;
- индексация поисковиками;
- удаление локальной базы или существующих резервных копий.

## Безопасность и эксплуатация

- В Git не попадают строка Neon, пароль владельца, TOTP-секрет или секрет сессии. Они задаются только в настройках API-проекта Vercel.
- Производственный API остаётся в режиме `CATS_HOUSE_ENVIRONMENT=production`: cookie передаётся только по HTTPS, а TOTP остаётся обязательным, если секрет задан.
- `robots.txt`, meta-тег и `X-Robots-Tag` продолжают запрещать индексацию.
- Перед импортом и перед переключением домена создаются независимые резервные копии. Локальный источник не удаляется до успешной проверки сайта и восстановления копии в тестовую базу.

## Критерии готовности

По основному HTTPS-адресу работают главная, карточка человека, дерево, поиск, вход владельца с TOTP, правки и загрузка/выдача фото или PDF. После обновления страницы сессия владельца сохраняется. Сайт не индексируется. Сверка счётчиков и выборочная проверка файлов подтверждают, что Neon содержит ту же базу, а проверенная резервная копия может быть восстановлена.
