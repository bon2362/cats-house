# Исследование: как строить линии семейного дерева

Дата: 6 октября 2026  
Статус: исследование; не является утверждённой спецификацией и не меняет код.

## Вопрос

Как показать происхождение, союзы и боковые ветви так, чтобы по линиям была
понятна фактическая связь людей, в том числе в режиме «Вся семья».

## Что проверено

### Реальные данные Cat's House

Проверен публичный ответ дерева для Петра Николаевича Кошкина. В данных есть
оба родителя его жены Марии Архиповой, их союз и родительские связи от этого
союза к Марии. Следовательно, непонятная связь с Агафьей Иосифовной не вызвана
потерей исходных данных: это ошибка отображения.

Текущий клиент сначала раскладывает людей в алфавитные строки поколений, а
потом добавляет линии. Семья не является единым объектом раскладки. Из-за этого
союз, шина детей и связанные семьи оказываются далеко друг от друга; при
неполном показе остаются визуально бессмысленные отрезки.

### «Древо Жизни»

На предоставленных владельцем снимках каждая нуклеарная семья показана как
локальный блок: партнёры стоят рядом, их дети выходят из одной точки или общей
шины, а дальнейшие семьи образуют отдельные ветви. Это делает очевидным путь
«родители жены → жена → её союз с выбранным человеком» и не превращает весь
набор в одну длинную шину.

### Gramps и Gramps Web

Gramps хранит семью отдельно от визуальной схемы: «семья» — это пара, её дети
или оба одновременно. В графовом представлении Gramps создаёт отдельный узел
семьи и связывает с ним родителей и детей. Это тот же смысловой промежуточный
узел, который нужен Cat's House.

Gramps Web не предлагает один режим «вся семья как дерево». Вместо этого он
разделяет предков, потомков, смешанное дерево (hourglass) и кратчайший путь
между двумя людьми. Документация прямо допускает повтор одной карточки в
нескольких семейных блоках при нескольких союзах: это осознанная цена
читаемости, а не ошибка.

### Алгоритмы раскладки

Иерархический алгоритм Graphviz `dot` ориентирует связи по направлению,
раскладывает их по уровням и пытается уменьшить пересечения. Он поддерживает
группы, кластеры, порядок выходящих связей и общие точки входа/выхода. ELK
Layered добавляет работу с составными блоками, фиксированными портами и
минимизацией пересечений. Эти возможности соответствуют задаче семейных
блоков; простая сортировка карточек в строке — нет.

## Выводы исследования

1. Базовой сущностью раскладки должен быть не человек, а **семейный блок**:
   два партнёра (или один известный родитель), узел союза и его дети.
2. Узел союза — единственная точка, из которой начинается ветвь общих детей.
   Круг показывается только в такой фактической точке ветвления, а не посреди
   произвольной линии.
3. Каждый путь линии обязан заканчиваться карточкой, узлом союза или явным
   элементом «продолжить ветвь». Обрезанная линия на пустом полотне запрещена.
4. Семьи размещаются и упорядочиваются до прокладки линий. Партнёры стоят
   рядом; дети одной семьи образуют соседний диапазон следующего поколения;
   сам семейный блок нельзя разорвать карточками другой семьи.
5. Родительская линия рисуется от порта узла союза к шине детей, затем к краю
   каждой карточки. Линия партнёрства — отдельный короткий маршрут между
   партнёрами через тот же узел. Путь не может проходить сквозь карточки.
6. У человека с несколькими союзами допустимо повторение карточки в разных
   семейных блоках, с явной ссылкой на одну запись человека. Это предпочтительнее
   длинных обходов и ложного впечатления, что дети относятся к другому союзу.
7. Режим «Вся семья» должен быть навигационной картой компонента, а не
   традиционным деревом: локальная главная ветвь остаётся разборчивой, удалённые
   семейные блоки раскрываются по требованию или сворачиваются в явные счётчики.
   Для точного ответа на вопрос «как связаны A и B» нужен отдельный режим
   кратчайшей цепочки, а не все линии сразу.

## Предлагаемая система правил для последующей спецификации

### Семантика

| Объект | Правило отображения |
| --- | --- |
| Союз двух показанных людей | Короткая линия между соседними карточками и один узел союза. |
| Ребёнок союза | Линия только от узла его союза; две одинаковые линии от каждого родителя не рисуются. |
| Один известный родитель | Одинарный семейный блок с подписанным неизвестным вторым родителем, если он есть в данных; иначе одна явная родительская линия. |
| Скрытый или исключённый участник | Карточка «Сведения скрыты» либо явный счётчик продолжения; никогда не пустой конец линии. |
| Несколько союзов | Один семейный блок на союз; повтор личности разрешён только между блоками и должен иметь ссылку на исходную карточку. |
| Связь, не помещающаяся в выбранный режим | Кнопка/маркер раскрытия с количеством скрытых участников, а не обрывок линии. |

### Раскладка и трассировка

1. Построить ориентированный граф семейных блоков из данных API.
2. Определить уровни поколений по родительским связям; союз остаётся на уровне
   партнёров и не меняет уровень сам по себе.
3. Разместить семейные блоки как неделимые группы, сохраняя детей одной семьи
   рядом и выбирая порядок, который уменьшает пересечения.
4. После измерения реальных размеров карточек назначить каждому блоку порты:
   `partner`, `children`, `parent`. Только затем строить ортогональные линии в
   свободных каналах между карточками.
5. Проверить маршруты на пересечение с карточками и другими обязательными
   маршрутами; при конфликте менять порядок блоков или занимать следующий канал,
   а не прокладывать линию через карточку.
6. Для всех режимов применять единые правила семейного блока. Меняться может
   только набор раскрытых блоков и глубина, но не значение линии.

### Режимы

| Режим | Правило объёма |
| --- | --- |
| Ближайшие | Выбранный человек, его родители, союзы, дети, братья/сёстры и их партнёры — только через видимые семейные блоки. |
| Предки / потомки | Однонаправленная иерархия; боковые семьи сворачиваются в явные маркеры. |
| Смешанное | Предки и потомки выбранного человека; супруги остаются внутри соответствующих семейных блоков. |
| Как связаны | Только кратчайшая проверяемая цепочка, с выделением используемых союзов. |
| Вся семья | Компонент связности как карта: у выбранного человека читаемое окружение, дальние блоки — свёртки и раскрытие. Не обещает показать 280 человек одновременно в традиционной древовидной форме. |

## Проверки, которые потребуются до реализации

- В тестовой фикстуре «родители жены → жена → супруг» существует непрерывный
  видимый путь и нет альтернативной ложной ветви.
- Каждый SVG-маршрут имеет оба допустимых конца: граница карточки, узел союза
  или интерактивный маркер продолжения.
- Удаление/скрытие человека не оставляет свободный сегмент линии.
- Дети конкретного союза выходят только из его узла; ни одна линия не пересекает
  карточку.
- В нескольких союзах дети не приписываются соседнему союзу из-за порядка
  карточек.
- Снимки реальных сценариев: Пётр Кошкин в «Ближайших», «Потомках» и «Всей
  семье»; отдельный сложный случай с несколькими союзами и с одним родителем.
